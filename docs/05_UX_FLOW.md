# 05 — UX Flow

## Primary navigation

- Today
- Runs
- Activities
- Goals
- History
- Integrations
- Settings

## Today

The home screen answers: **What should I run now?**

Sections:
1. Priority Runs.
2. Next Actions.
3. Blocked.
4. Resume.
5. Recent progress.

## Create Run

Minimal first step:
- title
- type
- outcome

Then optional clarification:
- priority
- next action
- due/review date

The UI should make creation fast and avoid a large form.

## Run detail

Show:
- outcome
- status
- progress
- next action
- blocker
- timeline
- related activities
- external links

Primary actions depend on state: Start, Pause, Block, Resume, Complete, Archive.

## Activity capture

A user can log an activity manually or receive it from an integration. The user can attach it to an existing Run or leave it as an unassigned activity for later review.

## Recovery UX

Blocked or paused Runs should remain visible. Recovery should be a first-class action: identify blocker → choose next action → resume.

## Design language

Calm, execution-focused, low-friction. Avoid dashboard overload, gamification pressure, and excessive configuration.
