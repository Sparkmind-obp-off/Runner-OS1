# 01 — Product Concept

## 1. Vision

Runner OS is an operating system for things a person is actively running. It turns scattered commitments into visible execution loops.

## 2. Problem

Traditional productivity tools optimize lists, notes, or calendars. Real execution also needs context, state, next action, blockers, progress, recovery, and history. Fitness and hobbies often live in separate apps, making the user's overall execution fragmented.

## 3. Core abstraction: Run

A **Run** is an active unit of execution. A Run can represent a project, task stream, routine, fitness plan, learning activity, hobby, or another user-defined activity.

A Run has:
- identity and type
- desired outcome
- current status
- priority
- next action
- due/review time when relevant
- progress
- blockers
- activity history
- optional external integration links

## 4. Product promise

At any moment, Runner OS should answer:

- What am I running?
- What matters now?
- What is the next action?
- What is blocked?
- What changed?
- What should I recover or resume?

## 5. Non-goals for the first MVP

- Full replacement for Notion, Jira, or a calendar.
- Social network.
- Medical/clinical tracking.
- Complex project-management methodology.
- Building every integration before validating the core loop.
- AI autonomy that can modify important user data without explicit controls.

## 6. Success criterion

A user can create a Run, define the next action, execute it, record progress, pause/block/resume it, and understand the current state from one dashboard.
